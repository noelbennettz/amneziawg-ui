# Third-party notices

The AmneziaWG Web UI image is a single container that carries the panel, the
AmneziaWG engine it drives, the command-line tools that engine needs, and the
Alpine Linux userland around them. This file lists every third-party component
in it, with the version, the licence as its own upstream or its own package
states it, and where its source is.

It is an inventory, not legal advice.

## What the image ships, and where the licence texts are

Licence texts the project can redistribute are installed in the image under
`/usr/share/doc/amneziawg-ui/`:

| File | What it is |
| --- | --- |
| `LICENSE` | The project's own licence, AGPL-3.0 |
| `THIRD_PARTY_NOTICES.md` | This file |
| `amneziawg-go.LICENSE` | MIT, from `amneziawg-go` at the pinned tag |
| `amneziawg-tools.COPYING` | GPL-2.0, from `amneziawg-tools` at the pinned tag |
| `NotoSansSC-OFL.txt` | SIL Open Font License 1.1, for the Chinese text face bundled into the WebAssembly frontend (`web-ui/internal/ui/style/font/LICENSE-OFL.txt`) |

Alpine packages carry their licence in the package database
(`/lib/apk/db/installed`) but do not install the licence text, so those texts
are **not** in the image: the table below names the package, its declared
licence and its upstream, which is where the text comes from. `apk info -a
<pkg>` in a running container prints the same declaration.

## Alpine Linux packages

Base image `alpine:3.24.1` (pinned by digest in the Dockerfile). The versions are
those the pinned packages resolve to in that release (`iptables~1.8`,
`iptables-legacy~1.8`, `bash~5.3`, `iproute2-minimal~7.0`, `openresolv~3.17`,
`tini~0.19`, plus what the base image and their dependencies bring), read out of
`/lib/apk/db/installed` in a built image. The licence is the package's own
declared SPDX expression, which is why some rows carry more than one.

Alpine does not install the licence texts into its images, and no text is
reproduced here: the record is the SPDX expression the package declares plus the
upstream location, which is where the text lives. Every published image carries
that same data machine-readably — an SPDX document generated by syft from the
pushed image, attached to the workflow run as `amneziawg-ui.spdx.json` and to the
image as an attestation (`cosign verify-attestation --type spdxjson …`). Where
this table and the SBOM disagree, the SBOM is right: it was read from the image
that was published.

## Unlicense packages

`scripts/check-licences.sh` - run by `.github/workflows/licences.yml` - checks the
Go modules against the strict allowlist Apache-2.0, BSD-2-Clause, BSD-3-Clause,
ISC, MIT. Unlicense is **not** on that list. Two packages of the frontend module
are public-domain dedications under Unlicense (OSI-approved and GPL-compatible),
and they are the one exception, named with their versions in the script:

| Package | Version | Licence | Text |
| --- | --- | --- | --- |
| `github.com/go-text/render` | `v0.2.1` | Unlicense (BSD-3-Clause for parts) | <https://github.com/go-text/render/blob/v0.2.1/LICENSE> |
| `github.com/go-text/typesetting` | `v0.3.4` | Unlicense (BSD-3-Clause, MIT for parts) | <https://github.com/go-text/typesetting/blob/v0.3.4/LICENSE> |

The strict check runs with exactly those two module paths ignored; the script
then reads go-licenses' report and fails if any other package is marked
Unlicense, if either of these two is at a version the script does not name, or
if one of them has stopped being a dependency and the exception has gone stale.
Bumping a version means editing the pair in the script and this table in the
same commit.

Both arrive through `fyne.io/fyne/v2`, the GUI toolkit the frontend is built
with, and neither is used by the server. Removing them would mean dropping
Fyne's text stack, so they are allowed and recorded here instead. No GPL-2.0-only
code is linked into either Go binary: the GPL components in the image are the
separate programs and scripts listed above, which the panel executes rather than
links.

## Source

The complete corresponding source of the GPL-2.0 components is the upstream
tree at the pinned tag, listed above; the Dockerfile clones exactly those tags
and builds the binaries from them. The panel's own source, including the
Dockerfile that produces the image, is this repository at the tag of the image
(`ghcr.io/noelbennettz/amneziawg-ui:<date>`).
